► Design system · v0.1

Warm, loud, built for the gym.

A focused design language for SwoleMate: warm cream surfaces, a hot-clay accent, gold for records, sage for progress, and one always-dark hero surface for live moments. Two themes that share the same vocabulary. Every token, component, and state lives on this page as a real rendering — not a screenshot.

Stack Svelte 5 · SvelteKit · Tailwind v4 · Skeleton v4 (replacing theme) Surfaces Today · Progress · History · Templates · Settings Voice Onest + Instrument Serif

Color — tokens

Every color is a CSS variable defined on :root for light and :root[data-theme="dark"] for dark. Components never hardcode hex values; they reach for tokens. Implementation-wise, drop the token block into app.css to override Skeleton's :root and ride the existing variant-* shims through the transition.

Elevation — three steps

One shadow vocabulary, three levels. Each token carries its own warm-brown (light) → near-black (dark) color, so a card looks correctly elevated in both themes without per-component overrides.

  • shadow-soft — chips, pills, hairline lift on the smallest elements.
  • shadow-card — default card depth. Most surfaces use this.
  • shadow-strong — hero, modals, device chrome, anything you want to feel "above the page".

Motion — quiet, with two heroes

Most of the app uses no motion. Three named animations carry the design language:

  • breathe — transform: scale(1) ↔ scale(1.03) over 4s ease-in-out infinite. Used on the consistency ring and timer dial — gives the active session a heartbeat.
  • pulse — opacity + scale over 1s steps(2) infinite. Live status dots, LIVE badges.
  • drift — translate(20px, -10px) scale(1.05) over 12–14s ease-in-out alternate. The two orb glows inside the hero card. Slow enough to be ambient, not distracting.

Transition timings: 120ms for hover/press, 180–240ms for theme change. Never animate page layout. Reduce-motion users get pulse + drift stopped automatically (TODO: wire prefers-reduced-motion).

Spill — segmented set pill

Replaces the production SetPillsHybrid.svelte. A horizontally-segmented capsule rendering 1 set (or N grouped identical sets) as: optional count, optional reps, optional duration, optional weight. Weight cell color-mixes with intensity based on the relative load within the group (the --w CSS var).

Spill — variants
Order: count? · reps? · duration? · weight?
10×100kg 9×102.5kg 8×105kg
3×8×22.5kg/side 6×27.5/22.5kg 2×10×BW 3×0:30
Segments
  • count — gold bg, white text. Only when ≥2 identical sets are grouped.
  • reps — bg-2 neutral. The "× reps" portion ("8×").
  • duration — clay-tinted 20% bg, clay-text. Used for timed sets ("0:30").
  • weight — color-mixes with clay using --w intensity (38–85% recommended).
  • weight.bw — neutral ink-tinted variant for bodyweight reps.
  • .pr modifier — gold border + glow + " ★" suffix appended via ::after.
Sizes
  • default — 12px font, 7×10 padding. Use in expanded exercise card.
  • .xs — 10.5px font, 5×8 padding. Use in dense list contexts (Past 2 Sessions, Last Time recap).
Grouping logic (port from existing SetPillsHybrid.svelte)

Sets group by key `${reps}:${duration}:${weight}`. Identical sets collapse into one pill with a count prefix. Non-matching sets get separate pills. Intensity scale uses total weight within the group: 0.38 + ((total - min) / (max - min)) × 0.47.

Stepper pill — numeric input

All numeric inputs in the live session log (reps, weight, time, per-side, left/right) use this unified component. Centered value (with optional unit suffix), − and + as integrated end segments. 52px tall, full pill radius. The value is tap-to-edit: clicking the number swaps it for an inline numeric input — Enter or blur commits (clamped to min/max), Esc cancels.

Implementation notes
  • The value is a content-sized inline element (not a fixed-width input). Wrap value + unit in .v-wrap (flex justify-center) so the group centers regardless of digit count.
  • Direct entry: the value renders as a button; clicking it focuses an overlay <input inputmode="decimal"> seeded with the current value (selected on focus). Blur or Enter parses, clamps to min/max, and fires onchange; Esc or a non-numeric entry reverts.
  • Per-side mode drops the unit suffix and uses the label "Per side · kg" instead — "kg / side" doesn't fit in the pill at 390px.
  • Split L/R uses two stepper-pills side by side, Reps spans full width on a row above.

Buttons — five variants

One primary, three secondaries, one celebratory. The primary CTA is the gradient clay pill; it's reserved for the single most important action on a screen (Log set, End session, Submit).

Button library
Variants in order of visual weight
When to use what
  • btn-primary — exactly one per screen state. Gradient + inset-shadow gives weight.
  • btn-success — sage gradient. Mark done, confirm-positive flows.
  • btn-ink — high-contrast utility action. Sync, Refresh, "Add" within forms.
  • btn-soft — secondary action, never standalone. Collapse, Cancel within a card.
  • btn-ghost — tertiary. Outline-only, low weight. Use template, secondary refresh.
  • icn-btn — icon-only actions: delete, toggle, close. Always pair with aria-label.

Charts — Chart.js theme integration

The mockup uses static SVG for chart previews. In production, charts go through chart.js (already a dep) with theme integration via lib/progress/charting.ts's existing ChartTheme + observeTheme helpers. Two universal rules:

  • Series 1 (primary) uses --clay with a vertical gradient fill (clay-2 top, clay 60% bottom).
  • Series 2 (overlay trend / secondary) uses --ink stroke + dots, so it reads against any underlying fill in both modes.
  • Bar value labels ALWAYS sit above bars, with a card-bg halo via paint-order: stroke; stroke: var(--card); stroke-width: 3px.
  • Grid lines use color-mix(in oklab, var(--ink-soft) 28%, transparent) — readable in both modes.
  • Axis labels use Onest 700 10px in --ink-2.
  • Yax notes use Instrument Serif italic 12px in --ink-2 with bold --ink inline values.

Migration plan — ordered, low-risk

Each step is independently shippable. The app never enters a half-migrated state where one screen looks "new" and another looks broken. We end Skeleton's grip on the visual layer gradually while keeping its primitives (modals, popovers) working.

Step 1 · Tokens + fonts (1 day)

  • Drop the token block into client/src/app.css under [data-theme='rocket'].
  • Add Onest + Instrument Serif preconnect + stylesheet to app.html.
  • Update Skeleton font tokens (--base-font-family, --heading-font-family).
  • Replace meta theme-color in app.html with #f3ece1 (light) — flip via JS on theme change.
  • Define the dark palette under [data-theme='rocket'].dark (rides existing dark-class toggle).

Verify: every existing screen should look "warmer" but otherwise functionally identical. No structural changes.

Step 2 · Core components (2–3 days)

  • Build lib/components/ui/: Card, Spill, StepperPill, Chk, Chip, Badge, Btn (with variant prop).
  • Refactor SetPillsHybrid.svelte to use .spill markup (keep grouping logic intact).
  • Add a PageHero component with variants: timer · consistency · plain.
  • Add SegmentedTabs and migrate ProgressTabs.svelte to use it.
  • Add BottomNav and migrate the mobile-bottom-nav markup from +layout.svelte.

Step 3 · Port Today (2–3 days)

  • Replace routes/+page.svelte's inline utilities with the new components.
  • Replace the SessionExercise.svelte add-set form with three StepperPill instances per mode.
  • Wire the live PR flash banner above the hero.

Step 4 · Port Progress + chart theme (2–3 days)

  • Update lib/progress/charting.ts's readTheme() to emit the new ChartTheme values (see mapping above).
  • Replace inline metric grids with MetricTile.
  • Replace RecentPrFeed's record rows with PRRow.
  • Replace ExerciseFocusPanel's stat trio with MetricTile and rep pills with RPill.

Step 5 · Port the rest + cleanup (2 days)

  • History · Templates · Settings · Admin · Backups · Help — mostly card-and-form pages.
  • Delete the v2 compat shims from app.css once nothing references them.
  • Migrate the codebase to Svelte 5 runes in the same pass (separate PR series).

Risks & mitigations

  • Chart.js theme observer already watches the .dark class. Verify it still fires when we add the data-theme attribute — patch the observer to watch both.
  • Form sizing on Safari/Firefox: field-sizing: content isn't universal. Use the span-with-input-overlay pattern in StepperPill until it lands.
  • Existing modals (EndSessionModal, EditWorkoutTimesModal) need focus-trap + Escape handler — track in a separate accessibility PR.
